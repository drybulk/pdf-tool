# PDF 도구 확장 계획: 미리보기, 이미지 저장, 메뉴 구조

## 1. 요약

- 쪽 미리보기와 이미지 저장에는 **pypdfium2**를 사용하는 것을 권장합니다. 라이선스가 Apache-2.0 또는 BSD-3-Clause 중 선택 가능한 허용 범위가 넓은 형태이고, 필수 의존 라이브러리가 없으며, 측정한 속도도 충분합니다.
- PyMuPDF는 성능과 기능이 우수하지만 AGPL-3.0 또는 상용 라이선스의 이중 체계입니다. 프로그램을 다른 사람에게 배포할 가능성이 있다면 부담이 되므로 후보에서 제외합니다.
- PDF를 이미지로 저장하는 기능은 **구현할 수 있습니다.** 다만 현재 사용 중인 pypdf는 쪽을 그림으로 그리는 기능이 없습니다. 따라서 pypdfium2가 필요하며, JPG로 저장하려면 Pillow가 추가로 필요합니다. PNG는 pypdfium2만으로 저장할 수 있습니다.
- 이미지 저장과 미리보기는 모두 쪽을 그림으로 그리는 기능에 의존하므로, pypdf만 사용하는 경량판에는 넣지 않고 **렌더링판**에 함께 넣는 구성을 제안합니다.

## 2. 용어 설명

| 용어 | 설명 |
|---|---|
| 렌더링(래스터화) | PDF의 쪽 내용을 화면에 표시하거나 이미지 파일로 저장할 수 있도록 픽셀(점) 단위의 그림으로 그리는 작업입니다. |
| 허용형(permissive) 라이선스 | 저작권 표기와 라이선스 문구를 유지하면 수정, 배포, 상업적 이용이 가능한 라이선스입니다. Apache-2.0, BSD-3-Clause, MIT-CMU가 여기에 속합니다. |
| AGPL-3.0 | 소스 공개 의무가 강한 라이선스입니다. 이 라이브러리를 포함한 프로그램을 다른 사람에게 배포하거나 네트워크 서비스로 제공하면, 프로그램 전체를 같은 조건으로 공개해야 할 수 있습니다. 혼자 사용하는 경우에는 이 의무가 발생하지 않는 것이 일반적이지만, 정확한 판단은 라이선스 원문이나 전문가를 통해 확인해야 합니다. |
| 지연 로딩 | 모든 항목을 미리 처리하지 않고, 화면에 보이는 항목만 필요할 때 처리하는 방식입니다. |
| 스레드 안전 | 여러 실행 흐름(스레드)이 동시에 호출해도 오류가 발생하지 않는 성질입니다. |

## 3. 후보 라이브러리 비교

| 후보 | 라이선스 | 설치와 의존성 | 평가 |
|---|---|---|---|
| **pypdfium2** | Apache-2.0 또는 BSD-3-Clause (선택). 렌더링 엔진 PDFium과 그 구성 요소에는 별도의 자유 라이선스가 함께 적용됩니다. | `pip install pypdfium2` 한 번으로 설치되며 필수 의존 라이브러리가 없습니다. 암호가 걸린 PDF도 처리할 수 있습니다. | **채택** |
| PyMuPDF | AGPL-3.0 또는 Artifex 상용 라이선스 | pip으로 설치할 수 있습니다. | 배포 가능성을 고려하면 제외 |
| pdf2image | 자체는 별도 라이선스이나, 변환 엔진인 Poppler(GPL 계열)를 별도로 설치해야 합니다. | 특히 Windows에서 실행 파일을 따로 설치하고 경로를 설정해야 하므로 사용이 번거롭습니다. | 제외 |
| Pillow | MIT-CMU (허용형) | pip으로 설치할 수 있습니다. | JPG 저장용으로 선택 사용 |

### pypdfium2 사용 시 유의 사항

- **배포 시 라이선스 문서 동봉**: pypdfium2에는 PDFium이 포함되어 있으므로, 바이너리 형태로 배포할 때는 PDFium과 그 구성 요소의 라이선스 문서를 함께 제공해야 합니다. 예를 들어 실행 파일(exe)로 묶어서 다른 사람에게 전달하는 경우가 이에 해당합니다.
- **스레드 제한**: PDFium은 스레드 안전하지 않습니다. 서로 다른 문서라도 여러 스레드에서 동시에 호출하면 안 되며, 한 번에 하나의 호출만 이루어지도록 보장해야 합니다. 이 프로그램에서는 렌더링을 메인 스레드에서 짧은 묶음 단위로 처리하는 방식으로 이 제약을 피합니다.
- **라이선스 문서 위치**: pypdfium2 5.6.0 배포본의 `dist-info/licenses` 폴더에는 pypdfium2 자체의 라이선스와 함께, PDFium이 사용하는 구성 요소(FreeType, libjpeg-turbo, libpng, zlib 등)의 라이선스 문서가 들어 있습니다. 배포할 때 이 폴더의 문서를 함께 제공하면 됩니다.

### Pillow 사용 시 유의 사항

- **라이선스**: MIT-CMU입니다. 과거에는 같은 취지의 문구를 HPND라는 이름으로 표기했으며, 2024년 9월에 OSI(오픈소스 라이선스 인증 단체)가 MIT-CMU를 인증 라이선스로 승인했습니다. 저작권 표기와 라이선스 문구를 유지하면 사용, 복사, 수정, 배포가 가능합니다. 광고나 홍보에 원저작자의 이름을 사용하려면 사전 서면 허가가 필요하다는 조항이 있습니다.
- **동봉된 네이티브 라이브러리**: Pillow 배포본(wheel)에는 이미지 형식을 처리하는 C 라이브러리가 함께 들어 있고, 각각 별도의 라이선스를 가집니다. Linux용 12.1.1 배포본에서는 libjpeg, FreeType, HarfBuzz, libtiff, libwebp 등이 확인되었습니다. 혼자 사용하는 경우에는 신경 쓸 필요가 없지만, exe로 묶어서 배포한다면 함께 들어가는 라이브러리의 라이선스를 확인해야 합니다. Windows용 배포본의 구성은 이 노트를 작성할 때 확인하지 않았습니다.

## 4. 기능별 필요 라이브러리

| 기능 | pypdf | pypdfium2 | Pillow |
|---|---|---|---|
| 쪽을 그림으로 그려 화면에 표시(미리보기) | 불가 | 필요 | 불필요 (Tk가 PPM 형식을 직접 표시할 수 있음) |
| 쪽 전체를 PNG로 저장 | 불가 | 필요 | 불필요 (표준 라이브러리 zlib로 PNG 파일 작성 가능) |
| 쪽 전체를 JPG로 저장 | 불가 | 필요 | 필요 (파이썬 표준 라이브러리에는 JPEG 저장 기능이 없음) |
| PDF에 삽입된 그림 파일만 꺼내기 | 가능 | 해당 없음 | 불필요 |

마지막 행은 "쪽 전체를 이미지로 저장"과 다른 기능입니다. 삽입된 그림 추출은 문서 안에 들어 있는 사진이나 도판 파일을 원본 그대로 꺼내는 것이고, 글자와 도형을 포함한 쪽 전체의 모습을 그림으로 만드는 것은 아닙니다.

### 이미지 저장 옵션(안)

- 저장할 쪽: 기존에 사용하는 범위 입력 방식(예: `721-732`)을 재사용합니다.
- 해상도: 72, 150, 200, 300 DPI 중에서 선택합니다. 내부에서는 배율 = DPI / 72로 변환합니다.
- 형식: PNG 또는 JPG(품질 선택)
- 파일명: `원본이름_p0721.png`처럼 쪽 번호를 포함하는 규칙을 사용합니다.

## 5. 성능 측정 결과

**측정 환경**: Python 3.12, pypdfium2 5.6.0, Pillow 12.1.1, 가상 화면. 본문 55줄, 래스터 그림 1개, 벡터 그래프 1개를 넣어 논문과 유사하게 만든 합성 PDF 200쪽 기준입니다.

| 작업 | 쪽당 평균 시간 |
|---|---|
| 썸네일 (배율 0.25) | 약 10.7 ms |
| 화면 미리보기 (배율 1.0) | 약 15.2 ms |
| 이미지 저장용 200 DPI | 약 37.6 ms |
| 이미지 저장용 300 DPI | 약 56.1 ms |

- 화면에 보이는 30쪽의 썸네일을 그리는 데 약 0.3초가 걸립니다.
- 800쪽 전체의 썸네일을 한꺼번에 만들면 약 9초가 걸리므로 지연 로딩이 필요합니다.
- 100쪽을 200 DPI로 저장하면 약 4초, 300 DPI로 저장하면 약 6초가 걸립니다.
- **한계**: 합성 PDF 기준의 수치입니다. 고해상도 스캔본처럼 쪽마다 큰 이미지가 들어 있는 문서는 더 느릴 수 있습니다. 또한 실제 문서의 PNG 파일 크기는 쪽당 수백 KB에서 수 MB에 이를 수 있으므로 저장 용량도 고려해야 합니다.
- **호환성 확인**: 렌더링 결과를 PPM 형식으로 변환해 Tk의 이미지 위젯에 Pillow 없이 표시할 수 있음을 확인했습니다. zlib으로 직접 작성한 PNG는 Pillow로 변환한 결과와 픽셀 단위로 동일했습니다.

## 6. 구조 계획: 경량판과 렌더링판의 분리

### 파일 구성(안)

```
pdf_common.py        공통 모듈: 쪽 범위 해석, 병합, 쪽 저장, 백그라운드 실행, 드래그 정렬 목록
pdf_tool.py          경량판 GUI (pypdf만 필요)
pdf_tool_render.py   렌더링판 GUI (pypdf + pypdfium2, JPG 저장 시 Pillow)
```

| 방식 | 장점 | 단점 |
|---|---|---|
| **공통 모듈 분리 (권장)** | 중복 코드가 없고, 수정이 한 곳에서 이루어집니다. | 실행에 파일 2개가 필요합니다. exe로 묶으면 이 문제는 사라집니다. |
| 독립된 파일 2개 | 각 파일 하나만 있으면 실행됩니다. | 같은 코드가 두 곳에 있어서 수정 때마다 양쪽을 맞춰야 합니다. |

### 렌더링판 화면(안)

- **왼쪽**: 쪽 목록이며, 각 행에 썸네일을 표시합니다. 행 높이는 썸네일 높이에 맞춥니다. 기존 드래그 정렬, 다중 선택, 자동 스크롤은 그대로 유지합니다.
- **오른쪽**: 선택한 쪽의 큰 미리보기입니다.
- **지연 로딩과 캐시**: 화면에 보이는 행의 썸네일만 생성하고, 최근에 만든 썸네일은 일정 개수까지 보관하여 스크롤할 때 다시 그리지 않습니다.
- **처리 방식**: 렌더링은 메인 스레드에서 몇 행씩 나누어 처리합니다(PDFium의 스레드 제한 때문입니다). 이미지 저장도 쪽 단위로 나누어 진행률을 갱신하며 처리하므로, 별도 스레드 없이 화면이 멈추지 않습니다.

## 7. 메뉴 막대와 우클릭 메뉴 계획

tkinter에 포함된 `Menu` 위젯을 사용하므로 추가 라이브러리가 필요하지 않습니다.

### 메뉴 막대(안)

| 메뉴 | 항목 |
|---|---|
| 파일 | PDF 불러오기, 새 PDF로 저장, 이미지로 저장(렌더링판), 종료 |
| 편집 | 실행 취소, 다시 실행, 선택 삭제, 전체 선택, 위치 지정 이동, 목록 비우기 |
| 보기 | 썸네일 크기, 미리보기 창 표시 여부(렌더링판) |
| 도움말 | 단축키 목록, 프로그램 정보 |

- 실행 취소와 다시 실행은 현재 단축키(Ctrl+Z, Ctrl+Y)로만 제공됩니다. 처리 동작이 `undo()`와 `redo()`로 이미 분리되어 있으므로, 메뉴 항목에 연결하기만 하면 됩니다.
- 메뉴 항목에는 단축키를 함께 표시하고, 실행 취소 기록이 없으면 해당 항목을 비활성화합니다.

### 우클릭 메뉴(안)

- 쪽 목록에서 마우스 오른쪽 버튼(`<Button-3>`)을 누르면 표시합니다. macOS에서는 `<Button-2>`와 Control+클릭도 함께 처리해야 합니다.
- 항목: 선택 삭제, 맨 위로, 맨 아래로, 위치 지정 이동, 이 쪽을 이미지로 저장(렌더링판)
- 선택 규칙: 우클릭한 행이 이미 선택된 행에 포함되어 있으면 선택을 유지하고, 포함되어 있지 않으면 그 행만 선택합니다.

## 8. 구현 순서(안)

| 순서 | 작업 | 규모 |
|---|---|---|
| 1 | 공통 모듈 분리, 경량판이 기존과 동일하게 동작하는지 회귀 테스트 | 작음 |
| 2 | 렌더링판: 큰 미리보기와 썸네일 목록 | 큼 |

## 9. 결정이 필요한 사항

1. **구조**: 공통 모듈 방식으로 결정되었습니다. 1단계에서 `pdf_common.py`로 분리했습니다.
2. **Pillow 포함 여부**: JPG 저장을 지원하려면 Pillow가 필요합니다. PNG만 지원한다면 pypdf와 pypdfium2만으로 구성할 수 있습니다. 논문과 보고서를 이미지로 옮길 때는 용량이 작은 JPG가 편리한 경우가 많아서 포함을 권장합니다.
3. **배포 계획**: 혼자 사용할 프로그램인지, 다른 사람에게 전달할 계획이 있는지에 따라 라이선스 문서 동봉 여부와 라이브러리 선택의 엄격함이 달라집니다.
